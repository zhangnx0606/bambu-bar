# LAN 超时回退云端与名称切换

## 背景

同一台打印机可以同时配置云端连接和局域网连接。应用默认优先使用 LAN，但当电脑离开打印机所在网段、打印机 IP 变化或网络静默丢包时，旧实现只能等待 MQTT 底层触发 `error` / `offline`，回退时间不可控，面板可能长时间没有进度、层数和温度。

此外，云端和 LAN 可以分别设置不同名称。旧实现合并设备时固定采用 LAN 名称，即使实际已经回退云端，面板仍显示 LAN 名称，无法直观看出当前数据来自哪条链路。

## 本次修改

### 1. LAN 首帧超时后强制回退云端

- 同一设备同时拥有 LAN 和云端配置时，仍优先尝试 LAN。
- LAN 在 8 秒内没有收到有效状态帧，主动停止 LAN 数据源并切换到云端 MQTT。
- 若 LAN 在期限内收到首帧，则取消回退计时器，继续使用 LAN。
- 设备被移除或连接生命周期结束时清理计时器，避免残留回调。
- 回退日志包含序列号、原传输、目标传输和原因，例如：

  ```text
  [printer-hub] 22E8BJ652101886: lan -> cloud (timeout)
  ```

### 2. 名称和连接标签跟随实际链路

注册表会同时保留：

- `cloudName`：云端设备名称，例如“其实我是2D打印机”。
- `lanName`：局域网配置名称，例如“P2S”。

面板按 `PrinterHub` 当前实际传输方式显示：

| 实际连接 | 面板名称 | 连接标签 |
| --- | --- | --- |
| 云端 MQTT | 云端名称 | 云端 |
| LAN MQTT | LAN 名称 | 局域网 |

当 LAN 自动回退云端时，名称与连接标签会同步更新，不再固定显示合并态或 LAN 名称。

### 3. 面板失焦自动收起

菜单栏面板失去焦点时自动隐藏，开发模式与正式模式保持一致。点击桌面、其他应用或面板外区域都会收起看板。

## 涉及文件

- `src/core/printer-hub.js`：LAN 首帧超时、云端回退和当前传输查询。
- `src/core/printer-registry.js`：分别保留云端名称与 LAN 名称，并按传输方式选名。
- `src/main.js`：记录传输切换日志，根据实际链路构建面板视图。
- `test/printer-hub.test.js`：覆盖 LAN 静默超时回退和 LAN 正常首帧不回退。
- `test/printer-view.test.js`：覆盖同一设备按云端/LAN 选择不同名称。

## 验证结果

- 全部 18 项自动化测试通过。
- 真实环境验证：原 LAN 地址不可达时，8 秒后输出 `lan -> cloud (timeout)`。
- 云端随后返回完整状态，包括任务进度、层数、喷嘴温度和热床温度。
- 应用当前使用 macOS `launchctl` 托管运行，不依赖临时 `npm start` 终端会话。

## 运行时限制

- 云端回退要求拓竹云端 MQTT 在当前网络可访问。
- `launchctl submit` 的临时托管可脱离终端持续运行，但电脑重启后不会自动恢复；正式开机自启仍建议使用打包后的 `.app` 登录项。
